- **Call signaling contract (server `src/socket.ts` `callEvents` loop)**: clients emit `call:initiate|call:offer|call:accept|call:answer|call:ice|call:reject|call:cancel|call:end`, payload REQUIRES `to` (target user id string, NEVER a socket object — that crashes socket.io-parser with `RangeError: Maximum call stack size exceeded`) + `callId`; dropped if `!to || !callId || to === userId`. Server relays verbatim to all of the target's sockets via `emitToUsers`. For `call:initiate` only, if the callee has no live sockets, server sends `call:unavailable {callId, to:caller}` back to the caller.
- **Handshake (both web + Flutter, keep in lockstep)**: caller creates pc + offer, emits `call:initiate` (payload `peer` = the CALLER'S OWN profile so the callee knows who's calling) then `call:offer` (the SDP). Callee buffers the offer + any ICE candidates until the user taps Accept, then sets remote SDP, answers, emits `call:accept` with its answer, flushes buffered candidates. Caller applies the answer on `call:accept`. 30s no-answer → caller emits `call:cancel` + "No answer". Busy → auto `call:reject`. `call:unavailable` → "Not available right now". Notices/toasts 3.5s.
- Webrtc: STUN only (`stun:stun.l.google.com:19302`, `stun:stun1.l.google.com:19302`), no TURN (media may fail only on restrictive NATs — accepted).
